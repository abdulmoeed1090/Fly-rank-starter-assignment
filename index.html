Refresh / Content Opportunity Scoring

Abstract: This project studies whether current search-performance signals can help prioritize pages for content review. A transparent Week-4 baseline score was compared with a Random Forest model using current-day impressions, clicks, average search position, and CTR. The evaluation used a time-aware split and a measurable next-day impression-decline proxy rather than a human-labelled refresh outcome. The Random Forest achieved higher ROC-AUC and Average Precision than the baseline, but the baseline performed better on the top-20 precision measure used for a small review queue. The result is therefore treated as directional decision-support rather than evidence that the model determines which pages should be refreshed.

1. Introduction / Problem Statement

Content teams cannot review every page with equal attention. This project asks whether observable search-performance signals can be used to prioritize pages for human review.

The system is designed as decision-support. It does not automatically decide that a page needs a refresh and does not claim to explain Google's ranking algorithm.

2. Data

The analysis uses the FlyRank ML Internship warehouse, specifically the fact_content_daily_performance data.

  • Working dataset: 50,000 rows
  • Start date: 2025-01-27
  • End date: 2025-02-26

Primary modeling signals:

  • GSC impressions
  • GSC clicks
  • GSC average position
  • CTR

Identifiers and future information were excluded from the predictive feature set.

3. Methodology

Future Outcome Proxy

Because the dataset does not contain a direct human-labelled "needs refresh" outcome, the experiment uses a measurable future-performance proxy.

For pages with at least 5 current impressions, a positive outcome is assigned when next-day impressions are at least 20% lower than current impressions. This is an observed future-decline proxy, not proof that a page needs a refresh.

Week-4 Baseline

The transparent baseline combines impressions, CTR and average search position:

0.4 × impressions + 40 × (1 − CTR) + 0.2 × average position

Random Forest

The Random Forest uses current-day impressions, clicks, average position and CTR. It produces a probability used to rank pages for review.

Validation

A time-aware 80/20 split was used because the outcome represents future performance.

  • Usable rows: 27,422
  • Training rows: 21,937
  • Test rows: 5,485

4. Results

Method ROC-AUC Average Precision Precision@20
Week-4 Baseline 0.4660 0.2865 0.3500
Random Forest 0.5107 0.3137 0.2500

The Random Forest achieved higher ROC-AUC and Average Precision, but the baseline achieved higher Precision@20.

Because Precision@20 directly represents the quality of a small review queue, the transparent baseline remains the stronger practical choice in this experiment.

5. Limitations & Honest Framing

  • The outcome is a future impression-decline proxy.
  • The working analysis uses a limited data slice.
  • Search performance can change for many reasons not represented here.
  • The experiment does not prove anything about Google's ranking algorithm.
  • The experiment does not demonstrate that refreshing content causes improved performance.

The findings should therefore be described as observed, measured, directional, and decision-support rather than causal or definitive.

6. Ranked Recommendations

  1. Review low-CTR pages. Investigate titles, descriptions, search intent and result relevance.
  2. Review low-position pages. Investigate content depth, topical coverage, search intent and internal linking.
  3. Monitor pages without strong warning signals. Avoid automatically intervening when the evidence is weak.
  4. Prefer the transparent baseline for a small review queue. In this experiment it achieved higher Precision@20 than the Random Forest.

8. Conclusion

The Random Forest produced measurable ranking signals for the defined future-decline proxy, but it did not outperform the transparent baseline on Precision@20.

The practical conclusion is therefore to retain the transparent baseline as the current decision-support starting point while treating the learned model as an experimental extension.

Better human-labelled outcomes, longer evaluation windows, additional validated signals and stricter validation would be required before relying on a learned model operationally.
